## FCM payload format (read-only explanation, no code change)

Sender: GoogleFcmPushAdapter -> POST https://fcm.googleapis.com/v1/projects/{pk.fcm.project-id}
/messages:send with Authorization: Bearer <OAuth2 token from the service account>
(GoogleServiceAccountTokenProvider), Content-Type: application/json, 20s request / 10s connect
timeout. DisabledFcmPushAdapter is the no-op fallback when pk.fcm.enabled=false.

Envelope is built with Jackson ObjectNode:
  { "message": { "token": ..., "notification": {"title","body"}, "data": {...} } }
- "notification" is OMITTED entirely when title AND body are both blank.
- "data" is omitted only when the map is empty (never happens: popupId is always set).
- All data values are Strings (mandatory = "true"/"false", popupId = push_task.id as string).
- There are NO platform overrides anywhere: no "android", no "apns", no "webpush". So no priority,
  no TTL, no sound, no click_action, no custom channel. data.clickUrl is passed in `data` only and
  the client must act on it itself.

Four shapes driven by PushPayloadAssembler.assemble() on pushType:
- internal          -> data-only, type=IN_APP_POPUP, mandatory, path            (no notification block)
- external          -> notification + data, type=EXTERNAL_NOTIFY, clickUrl?
- all               -> notification + data, type=IN_APP_POPUP, mandatory, path, clickUrl?
                       (type is IN_APP_POPUP because includesInternal() is checked first)
- clear_required    -> data-only, type=IN_APP_POPUP_CANCEL, popupIds="101,102,103"

data key order (LinkedHashMap): popupId first, then type, then the rest.
path = (internalUrl or "/in-app-popup") + query, URL-encoded UTF-8, keys in order:
title, body, button, showOn (comma-joined pushPages), bannerUrl, url. Uses '&' when the base
already contains '?'.

Lasting note: because internal-only pushes are DATA-ONLY and carry no apns overrides, iOS will not
fetch them in the background at all (no content-available/aps payload) and Android normal-priority
data messages are deferred in Doze. This is exactly why the client-side pull fallback exists
(GET /push/popups/pending, PendingPopupItemResponse mirrors popupId/type/mandatory/title/body/path/
showOn/clickUrl so the client parses pushes and pulled popups alike - note the pulled item exposes
showOn as a separate field, whereas the FCM path only carries it inside the path query string).

FCM data size guard: PushPayloadAssembler.assertDataSize, FCM_DATA_MAX_BYTES = 4096, but the math
is `(key.length() + value.length() + "type".length()) * 2` - the +4 constant is meaningless and
chars*2 is not the UTF-8 byte length, so non-ASCII values are mis-estimated. Still unfixed.
